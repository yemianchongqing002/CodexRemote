# 远程审批与会话权限

打开一个聊天后，网页和原生客户端读取该聊天的桌面实时快照。自动更新模式下，每五秒刷新一次审批、访问权限和模型；手动更新模式下，点击右上角同步按钮或圆形聊天刷新按钮都会重新读取审批与权限。切换聊天、离开页面或断线后，旧审批按钮不可用。此功能不提供后台系统推送，也不扫描未打开的其他聊天。

## 审批

命令执行、文件修改和额外权限申请显示在输入框上方。卡片展示具体命令、目录、文件差异或申请权限，用户点击允许或拒绝后回传桌面。命令按钮遵循桌面提供的可选决定；额外权限仅授予本轮原始申请的范围。不提供永久规则或自动批准。桌面没有提供文件差异时，卡片会提示在电脑核对。

提交前重新读取待审批请求，校验会话、请求标识与内容摘要；内容变化或请求消失返回过期状态。提交后回读确认请求已移除。连接中断不自动重发决定，界面提示刷新核对。只读服务不能执行这些操作。系统授权弹窗、Guardian 自动审查拒绝、登录和 MCP 专用交互不属于这三种审批接口。

## 权限同步：读取 Codex 会话状态

主动同步的方向是 Codex → 网页。审批模式按钮显示 Codex 会话 `latestThreadSettings` 中的状态，修改后也以会话回读结果为准。桌面菜单独立保存的选择可能与会话设置不同，不用于覆盖会话模式按钮。

服务读取所配置 `--codex-home` 下 `.codex-global-state.json` 的 `electron-persisted-atom-state.agent-mode-by-host-id.local`，在实时响应的 `permissionSelection` 中返回已识别的桌面选择。该字段仅用于补充展示桌面选择，`canChange=false` 指不能修改桌面选择，不限制会话审批模式修改。按钮使用原始会话权限字段显示模式；桌面选择读取失败不阻止会话模式修改，会话快照读取失败则禁用操作并提示同步。该读取针对本机保存的菜单选择，不代表已验证所有自定义配置、模型强制审查策略与远程 host 的有效权限组合。

手动同步会取消旧轮询并使旧响应失效，避免用户点击被正在进行的请求跳过。同步成功后覆盖网页权限显示与模型草稿；模型不完整时保留模型草稿并提示。同步失败明确显示原因，后台轮询成功不会静默清除该错误，下一次主动同步成功才清除。重复点击同步合并为一次请求。提交审批决定期间禁止同步，以免中断写入。

## 权限修改限制

当前 follower `thread-follower-update-thread-settings` 只能修改会话设置，不能持久更新桌面独立保存的权限选择。它返回 `{ok:true}` 并短暂回读成功，也不意味着桌面菜单已改变；下一轮桌面可能重新发送原选择，覆盖会话设置。

这里的“临时”不是只生效一轮或经过固定时间就失效，而是不能保证会话设置不被后续操作覆盖。当前已接入的 follower 接口未提供持久修改桌面菜单选择的入口；这不代表已证明 Codex 的所有接口都不具备该能力。

网页允许修改会话默认审批模式，不承诺同步修改 Codex 桌面菜单。选择菜单下方直接说明：“在此设置会话默认审批模式，对后续轮次生效；Codex 桌面选项不会同步修改。”设置页不再重复说明。

`POST /api/thread/permissions` 校验权限版本后只提交一次会话设置修改，并回读权限配置、审批策略和审查方，匹配才报告“会话审批模式已更新”。过期版本返回 HTTP 409；回执失败或回读不一致明确提示核对，不自动重发。修改不保证改变已经执行中的操作。已有待审批请求的允许、拒绝、取消独立处理。服务不写入 Codex 的全局状态文件。

### 一直从网页发送，是否会沿用会话权限？

有条件地可以，不能仅凭消息来自网页就保证。当前发送实现 `internal/desktop/client.go` 在开启新一轮时使用 `thread-follower-start-turn`，设置 `context.inheritThreadSettings=true`，没有每轮显式传入网页自己的 `approvalPolicy`、`approvalsReviewer` 或 `permissions`。运行中的追加消息使用 `thread-follower-steer-turn`，也不携带权限修改。

核对本机 Codex 桌面实现后，普通继承路径会优先从 `latestThreadSettings` 取权限参数。因此，如果会话权限已经成功修改，并且没有其他入口重写，也没有进入使用服务默认权限等分支，连续通过网页开启新轮次可以沿用这份会话权限；不会仅因为桌面菜单仍显示另一选项，就必然在每次网页发送时重置。

以下边界必须区分：

- 从 Codex 桌面发起新轮次、再次修改权限或其他客户端写入，可能改变后续轮次继承的设置。
- 继承的是届时的会话设置，并非网页独立保存且每轮强制提交的偏好。服务默认权限、配置要求等分支仍可能影响最终生效值。
- 当前版本允许修改会话默认审批模式，但没有在每轮发送时强制重设权限。继承结论来自发送代码和本机桌面实现核对，没有通过真实会话连续切换权限进行验证。
- 主动同步以 Codex 会话状态覆盖网页显示。桌面保存的菜单选择仅作补充说明，不能冒充会话当前默认设置。

## 兼容与接口

读取使用桌面 follower IPC：`thread-stream-following-changed` 版本 1 请求快照，读取 `thread-stream-state-changed` 版本 11。审批仅向原会话 owner 提交，不另起 app-server 或接管会话写入。未知协议版本明确报错。

接口为 `GET /api/thread/live?threadId=...`、`POST /api/thread/approval` 和 `POST /api/thread/permissions`，沿用认证、Host、Origin 与只读限制。`permissionSelection` 包含 `agentMode`、`source`、`canChange` 与 `reason`；`permissionVersion` 同时覆盖会话状态和桌面选择。

回归测试覆盖桌面选择与旧会话状态矛盾、手动同步替换轮询、过期响应、失败提示、模型草稿、移动端显示，以及版本校验、单次 IPC 写入和延迟回读确认。真实服务仅做读取验证，不通过测试修改用户权限。

2026-09-13 协议兼容修复：权限修改优先使用 `thread-follower-update-thread-settings` v2，校验 `applied:true`；`applied:false` 作为未应用处理。仅当路由未转发请求（没有 handledByClientId）且明确返回 no-client-found 或 request-version-mismatch 时尝试 v1，并校验旧版 ok 回执。超时、回执不确定及处理方返回错误不重发。本机新版 Codex 已通过不满足条件的空设置请求确认 v2 回执，未修改真实权限。
