# 架构与职责

## 组成

- **服务 A**：直接提供网页、聊天 API、SSE、发送队列及图片接口；读取目标电脑的 Codex 日志。
- **守护 B**：保存启动配置，启动和恢复 A。A 只负责检测并恢复 B；B 每次启动都重新读取配置并重启 A。
- **系统启动脚本**：Windows 计划任务或 macOS LaunchAgent 启动的外层程序，等待网络并低频检查 A/B。
- **客户端**：Tauri 外壳负责本机网络和连接管理，聊天页面与浏览器共用 `internal/server/web`。

聊天流量直接进入 A，B 不转发 HTTP。A/B 使用私有本机管理通道；目标电脑之间不共享队列或配置。具体恢复、停止和日志流程见[双守护](guardian.md)。

## 实时状态与控制的代码分层

调用链为网页或客户端 → `internal/server/live_handlers.go` → `internal/desktop` → Codex 桌面 IPC。HTTP 层负责请求校验、会话存在性检查、超时和状态码；桌面适配层负责协议、快照解析和操作回读。两层各自承担不同职责，不是重复实现。

| 文件（位于 `internal/desktop`） | 职责 |
| --- | --- |
| `wire.go` | IPC 握手、接收方发现、请求路由与统一封包，保留是否已发送的判定 |
| `client.go` | 消息发送、引导及启动回合 |
| `live.go` | 实时连接、取消与清理，以及读取状态的入口 |
| `live_stream.go` | 订阅快照、协议版本与来源校验 |
| `live_state.go` | 快照数据结构、解析、审批提取与状态摘要 |
| `approvals.go` | 审批决定、过期检查和操作回执 |
| `permissions.go` | 权限设置白名单、提交与回读确认 |

审批和权限修改共享同一把控制锁。操作只提交一次，回读仅用于确认状态；后续重构应保留这些约束。相关 HTTP 边界测试在 `internal/server/live_handlers_test.go`，桌面行为测试在 `internal/desktop/live_test.go`，封包与发送状态测试在 `internal/desktop/wire_test.go`。

## 侧栏数据与 Codex 一致

网页与客户端使用目标电脑 Codex 保存的项目和任务元数据：项目名称、顺序和任务归属来自 `.codex-global-state.json` 及桌面 SQLite 项目表，任务名称、最近活动顺序、归档状态和类型来自 `state_*.sqlite`。读取使用只读 SQLite 连接，包含 WAL 中尚未检查点的数据，不修改 Codex 数据。适配逻辑在 `internal/chat/desktop_index.go`，侧栏输出在 `internal/chat/sidebar.go`。

侧栏分为“项目”和“最近”：只展示已保存项目；未关联项目的任务直接展示任务标题。旧任务缺少显式归属时，只匹配已保存项目的精确根目录，显式项目归属和独立任务标记优先。空项目保留，不可访问的项目目录显示为灰色。语音、内部审批和已删除任务不因日志残留重新出现。默认列表不展示已归档任务。

`/api/threads` 返回 `projects`、`threads` 和 `sections`，前端按项目 ID 分组，不以工作目录生成项目。元数据变化会触发同步版本变化；读取失败或数据库结构不兼容时返回提示和空侧栏，不回退到推测条目。目录仍用于文件访问和创建校验，创建入口仅接受已保存项目根目录。

该目录是连接电脑的本地 Codex 目录，不包含其他电脑或 ChatGPT 云端会话。桌面数据库及状态文件属于版本相关适配；升级后应重新验证名称、归属、过滤和顺序。

## 聊天读取与同步

服务按需扫描 `sessions` 和 `archived_sessions`，记录文件标识与读取偏移。只消费完整 JSONL 行，截断或替换时重建索引；规范事件和镜像消息去重。不复制原始日志到项目目录。

SSE 通知数据版本变化，页面再读取所选聊天。前台默认每 3 秒检查已发现日志、约每 15 秒发现新日志；连接心跳每 30 秒一次。无订阅时不持续扫描，读取请求和排队调度仍可触发按需刷新。

消息按页加载，手机 DOM 最多保留 200 条。每会话文字缓存最多 500 条 / 2 MiB，总文字缓存 32 MiB；这些是缓存限额，不是整个进程的内存上限。消息落盘时间由 Codex 决定。

## 发送与创建

已有聊天通过桌面 follower IPC 接收文字或图片。新建聊天使用短时本机创建器保存首条输入，释放写入锁后交给桌面处理。队列、回执和图片存储独立于 Codex 日志。

详见[发送协议](sending.md)与[排队及创建](queue-and-create.md)。

## 访问与显示

默认监听回环地址。登录使用服务访问口令及 HttpOnly Cookie；服务检查 Host 和 Origin，不向网页暴露任意 IPC 方法或文件路径接口。媒体访问须关联到消息引用或受校验的上传图片。

前端渲染 Markdown、代码、公式和按需媒体，清理不安全 HTML 与 URL。渲染库随程序分发，不从 CDN 加载。服务没有外发分析或远端聊天存储。

## 资源策略

前台只维护当前连接和聊天；后台关闭同步，恢复后补齐。空队列不定时检查磁盘，有队列时只检查相关聊天。媒体按需加载，隐藏页面时暂停播放。不使用常亮、推送或后台同步。

客户端的连接隔离与生命周期见[客户端说明](../client/README.md)，验证状态见[验证说明](verification.md)。
